# Google Play publishing

The project owner controls the Play Console account, signing credentials, testing track and release approval. Start account verification early enough to resolve paperwork or device issues. The account and the first internal release are independent of publishing the app publicly.

## Create and verify the publisher account

1. Choose a Google Account you intend to keep as the FedLeave publisher. Sign in to Play Console with that account. Review and accept the Developer Distribution Agreement and pay Google's **one-time US$25 registration fee**. An account holder must be at least 18. [Play Console signup](https://play.google.com/console/signup) · [Registration help](https://support.google.com/googleplay/android-developer/answer/6112435?hl=en)
2. Use **Personal** if publishing as an individual. Use **Organization** when a genuine organization owns and publishes the app. Google requests legal identity, address and contact information. Organization verification normally requires a matching D-U-N-S number. Review the public developer profile and your obligations before choosing. Record the selected account type and owner in the release checklist. Keep identity documents and account recovery material outside Git. [Required account information](https://support.google.com/googleplay/android-developer/answer/13628312?hl=en)
3. Complete the identity verification shown in Console. For a new personal account with a device-verification task, open the task on Play Console Home, follow its QR code, and verify from the Play Console mobile app while signed in as the owner. Google specifies a non-rooted physical phone running Android 10 or newer. [Device verification](https://support.google.com/googleplay/android-developer/answer/14316361?hl=en)

## Create the listing and signed candidate

| Owner task | Deliverable |
| --- | --- |
| Choose the permanent package | Confirm the final Android application ID before creating the Play app entry. Set default listing language, app category, countries and pricing. Use FedLeave branding approved by the owner. [Create and set up an app](https://support.google.com/googleplay/android-developer/answer/9859152?hl=en) |
| Produce the first signed candidate | In Android Studio, generate a signed Android App Bundle (`.aab`) for the release variant. Choose Play App Signing. Use the upload key to sign uploads and let Play sign delivered APKs. Store the upload key and recovery instructions securely under the owner account. Record the key fingerprint, version name and increasing version code. [App signing](https://developer.android.com/studio/publish/app-signing) |
| Check Android support | For a phone app submitted on November 20, 2026, Google's published minimum submission target is **Android 16 / API 36**, effective August 31, 2026. Check again before upload. The provisional install floor is API 26 and is set independently. Confirm native ABI and 16 KB support for bundled Python dependencies, if used. [Play target API requirement](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en) · [Native compatibility](https://developer.android.com/guide/practices/page-sizes) |
| Prepare store assets | Use screenshots of the real candidate with fictional records. Supply icon, feature graphic, short and full description, support contact, release notes and other console-requested metadata. Describe offline leave tracking, compatible backups, and native sharing accurately. [Store listing setup](https://support.google.com/googleplay/android-developer/answer/9859152?hl=en) |
| Complete content and privacy forms | Publish a privacy policy and link it in the Play listing and app. Complete Data safety, content rating, audience, ads and access declarations according to the actual signed build and bundled dependencies. Verify any processor, telemetry, backup behavior and network access before answering. Describe private local records and user-initiated sharing accurately. [Data safety](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en) · [Privacy policy requirements](https://support.google.com/googleplay/android-developer/answer/10144311?hl=en) |

## Test tracks and first production release

1. **Internal.** Upload the signed candidate and install it from the internal track on a phone. Confirm the version, offline behavior, Android file picker and Share, and a real app update. Use the [release rehearsal](developer-setup-and-testing.md#before-calling-a-build-ready) and storage gates. Share the internal test link only with intended testers.
2. **Closed.** Recruit actual testers with a range of Android phones. Give them a synthetic backup and short tasks covering first use, balance selection, leave edits, sharing and restore. Record device model and version, feedback, defects and what changed. For personal developer accounts created after November 13, 2023, Google's current requirement is **at least 12 testers opted in continuously for the preceding 14 days** before applying for production access. Record when this requirement is met in Console and allow time for review. [New personal account test requirements](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)
3. **Production access.** Where required, apply in the Play Console dashboard and describe how the closed test was conducted, what testers reported, what changed, and why the candidate is ready. Close release-blocking issues and complete the [four desktop GUI round trips](device-storage.md#compatibility-and-recovery-checks).
4. **Production.** The project owner checks the submitted build, declarations, availability and listing for accuracy before starting the Play review. Record the approved build and when it goes live. Install it from the real listing on a supported phone and perform an offline smoke check and a restore using synthetic data. Route post-release reports to the known support channel. [Prepare and roll out a release](https://support.google.com/googleplay/android-developer/answer/9859348?hl=en)

The 14-day closed test for eligible accounts and Google review are calendar dependencies. Organize the local build, test, asset and checklist work into separate five-hour milestones. The account owner approves enrollment, tester communication and submission.
