# Reports, data, and preferences

This inventory extends the app specification to the desktop Calendar menus, Analytics companion, chart tools, and relevant data commands. The [parity matrix](../parity.md) records the Android disposition and acceptance case for each capability. The screenshots and data contracts are the deliverables of later milestones.

## Reports

Reports opens on a useful year and shows that leave year and its actual dates. A year change or **Refresh** reloads a read-only snapshot. Each result keeps its year, filters, and snapshot identity. Show progress, empty results, warnings and retry on failure. Keep a rejected, cancelled, or obsolete result from replacing the current selection. A chart's exact-value table and any supporting transactions use the same result as the graphic. Use an explicit **View entries** action for contributing records and retain the report's scroll position and filters on return.

## Data and maintenance

**Data and backups** exposes **Share backup**, **Restore backup**, and the data health check. Read and write the CLI's schema-v1 portable archive and accept the compatible single-year input. The working ledger uses the same canonical desktop JSON. Archive merge keeps an existing transaction when its ID collides within that year and adds incoming IDs that are absent. Existing configuration and holiday-cache files stay authoritative in merge mode. Replace acts on included matching files and preserves unrelated years. Preview before writing, including collision counts and any dependency or validation issues. The storage milestone defines the complete validation, interrupted-restore recovery and Windows and Linux round-trip cases. [Desktop backup/import code](../../../src/fedleave/commands/data.py#L286) · [Backup tests](../../../tests/test_export_import.py)

**Import WMS leave report** accepts the supported FRC-E clocking report HTML through the system picker and parses it as data. Preview dates, mapped types and hours, ignored regular-time rows and which stored date/category/direction rows would be replaced. Unsupported leave codes or malformed HTML structure produce a useful problem report before writes. Surface pending leave-year setup and confirm the actual schedule for any uncovered date. Preserve unrelated leave records and identity across a repeat import where the mapped content matches. For a manual payroll reconciliation, propose an advanced action on the source transaction or day, with the matched row and new hours reviewed. When multiple rows match, require the user to choose one. Confirm whether the separate manual action is needed with the WMS owner. [Desktop WMS GUI](../../../src/fedleave_gui/main_window.py#L1973) · [Parser and mapping](../../../src/fedleave/wms_import.py) · [Payroll reconciliation](../../../src/fedleave/commands/transactions.py#L456)

**Check data** is read-only and reports relevant malformed ledgers, invalid rows, and lineage warnings with the affected year. **Review carryover** includes recovery and opens the relevant generated-record review. For duplicated legacy opening mirrors, offer explicit repair only after identifying an affected ledger and showing old and revised values. Review and separate confirmation are required. [Desktop validation](../../../src/fedleave/commands/data.py#L562) · [Legacy repair and recovery](../../../README.md#preview-source-edits-and-reconciliation)

## Calendar settings and help

- A year chooser lists discovered leave years and real dates. It moves Calendar browsing in the chosen year. The one balance panel stays at Today until a date is chosen through **Change date**. Reports can independently select an available year. Reopen Calendar on the current date. Use **Refresh** to reread local data when a workflow provides it. [Desktop year chooser](../../../src/fedleave_gui/main_window.py#L2334) · [Year metadata](../../../src/fedleave/commands/data.py#L35)
- Give the user Sunday or Monday as the week start, a 0–13 day payday offset for display, and Calendar visibility controls for automatic accruals, holidays, paydays and period ends. Respect Android font scaling. Treat payday and marker controls as presentation choices. They leave accounting cutoffs intact. The balance picker always identifies pay-period ends. Keep reminder thresholds as local choices in pay periods with the desktop's default 1, 3, 6, and 12. Keep print format choices in the print or share preview if the artifact supports them. [Calendar preferences](../../../src/fedleave_gui/main_window.py#L564)
- Holiday handling reads compatible cached dates offline. Provide a way to review dates, regenerate from supported offline rules, and select a local agency calendar ICS. The initial release uses these offline sources and preserves the last valid cache on failed refresh. [Device storage decision](device-storage.md#canonical-private-storage) · [Holiday commands](../../../src/fedleave/commands/holidays.py) · [Holiday dates and cache](../../../src/fedleave/holidays.py)
- Accounting settings show the work tour, increment, accrual defaults, and category policies used for results. Provide a review step for changing the tour or recording the actual date from which FMLA history is complete. Preserve captured tours on past transactions. Keep unsupported editing fields readable and carry them intact through backup. Decide which agency-specific rules need direct editing after comparing existing stores. [Desktop config model](../../../src/fedleave/config.py#L23) · [FMLA history guide](../../../docs/PARENTAL_LEAVE.md)
- Expose app help, leave abbreviations, version and project/site information. Help is bundled, searchable or grouped by task, and written in app terms. Give version detail for support and identify the project website as an external navigation action. Use platform font scaling, normal Android Back, and system behavior for app and store updates. [Desktop help and About](../../../src/fedleave_gui/main_window.py#L2303)

## Desktop-specific and deferred features

- The first release defers What-if Planner. Planned entries in the real leave ledger and dated projections remain in scope. [Issue #147](https://github.com/joshua-guthrie/fedleave/issues/147)
- Android uses a private built-in data store and calculator. Alternate backend executables, arbitrary working-data directories, desktop installer update prompts, a persistent PDF destination, and forced close are desktop controls. The phone uses private storage, backup restore, platform sharing, Play updates, and normal app navigation. [Desktop settings](../../../src/fedleave_gui/settings.py) · [Calendar menus](../../../src/fedleave_gui/main_window.py#L1511)
- CLI aliases, output modes, raw developer snapshots and command help remain developer tooling. The phone exposes the user workflows with app labels. MCP and AI integrations stay on desktop. Reports or charts may be shared as the supported graphics and PDFs. The phone provides an on-screen table for exact chart values.
