FedLeave Calendar Help

FedLeave Calendar is a graphical month view for the fedleave command-line backend.

Official project website: https://www.westmouthbay.com/fedleave-application/

Creating a New Leave Year

Start New Leave Year offers Manual Starting Balances with No Previous Leave Year, or Carry Over From Previous Leave Year. Manual mode retains the starting-balance inputs. Before creating, the GUI warns that previous-year balances, earned dates, lot history and expiration information will not be imported, even if no older files exist. Cancel creates nothing. Ordinary manual CLI init has no corresponding generic warning.

Carryover disables manual amounts. Select a valid adjacent predecessor returned by the selected CLI, then request a preview. Review opening hours, cap reductions, original lots, dates, deadlines and material warnings before confirming. A changed selection invalidates the preview. Source/policy changes reject stale apply; preview again. Both modes refuse an existing destination. All canonical reads and writes use the configured CLI and data directory; the GUI never writes a ledger.

OPM 2026 ends January 9, 2027; 2027 starts January 10. Actual 26/27-period schedules are validated. Expiration dates are inclusive last eligible usage dates, with use disallowed the following day. A manual expiring opening has unknown provenance; no fictitious earning date or renewed entitlement is created.

Changed source years produce STALE_CARRYOVER with recomputed read-only balances. Use Tools > Reconcile Carryover to preview and explicitly apply the full chain, or use fedleave carryover-reconcile --year YEAR --preview --json, review all affected years, then explicitly apply. Genuine destination activity is preserved. Interrupted reconciliation requires --recover. Manual years remain independent.

Paid Parental Leave (PPL) and FMLA

In the day editor add Paid Parental Leave (PPL) and choose Earn. New Earn entries suggest an editable 480-hour standard full-time example; existing values are retained. The earned date is treated as the start of the 12-month use window. Enter the actual qualifying date. There is no separate event field. PPL cannot be paid out or extended.

PPL Use automatically consumes FMLA exactly once. Manual Family and Medical Leave Act (FMLA) offers Use only and means additional non-PPL FMLA usage. It adds no physical absence. Same-day combinations require clarification; never mirror PPL hours as manual FMLA.

The balance status and expiration dialog show source IDs, last eligible and first ineligible dates, scheduled/protected use and potential or expired loss. FMLA is a negative within-period usage tracker, not paid leave or a spendable bank. Its period begins with first actual use, independently of PPL's earned date or the federal leave year. Future or unresolved use is provisional.

Capacity is N/A until relevant history is reviewed and rules.fmla.history_complete_from is supplied in config.json. Missing historical tours are explicitly unverified. The limit is twelve administrative workweeks; the configured schedule or agency-confirmed rules.fmla.weekly_hours determines its hour equivalent. Existing linked successor years reflect source corrections immediately. Manual years remain independent. These results do not determine agency eligibility or approval.

Policy guidance: OPM PPL and OPM FMLA.

Calendar Layout

The main window shows month navigation, a calendar grid, pay periods touching the displayed month, and balances as of today. Each pay period has its own Type, Earned, Used, and Balance table.

Day Cells

Each day cell shows the day number, nonzero leave entries, holidays, pay days, and pay-period endings. Zero values are intentionally not shown.

Day Editing

Click a day to edit supplied leave categories authoritatively. Select Use or Earn for each leave type and enter positive hours; newly added leave types default to Use. Saving calls the fedleave backend and reloads the month from backend JSON.

Leave Charts

The View menu includes a Leave Charts submenu for annual leave, sick leave, credit hours, comp time, travel comp, and time-off award charts. Each chart opens in its own window and offers Save PNG, Save PDF, and Print actions.

Analysis > Analytics opens the read-only FedLeave Analytics companion using the same backend, resolved data directory, displayed leave year, font size, and report folder as the calendar. Its Summary, Seasonality, Calendar Heatmap, and Overtime, Comp, and Credit pages report hours and include qualifying future scheduled entries. Planning contains the What-if Planner.

What-if Planner

Choose Analysis > Planning > What-if Planner..., or Planning > What-if Planner in Analytics. Set a cutoff, horizon inside the selected initialized leave year, scenario name, category, and optional reserve. The cutoff defaults to today within that year's bounds; the horizon defaults to the actual leave-year end. Reserves are per category, in hours. Equality is allowed; a breach means a daily closing balance below the reserve.

File > Help... (F1) in Analytics opens detailed offline instructions for the active tool, including examples and action differences. Hover over buttons for short explanations. Add tentative use adds extra use alongside existing bookings. Click a draft Date cell (or press Space/Enter) to open a calendar bounded after cutoff through horizon; Cancel preserves the original text. F2 also permits ISO date entry. Date selection does not guarantee working capacity.

Replace scheduled use... and Remove scheduled use... open a dialog listing effective future bookings. Check the ones you intend to change; no background selection is required. Existing selections are prechecked, and Cancel adds no operation. Replace omits those originals in the scenario and adds one editable replacement with their combined hours and first booking's date/category; review those defaults. Remove only omits originals from the scenario. The baseline and ledger keep all originals. Recorded, synthetic and accrual rows cannot be targeted; already-targeted originals are unavailable until the earlier change is edited/undone.

Undo selected changes deletes draft operations: Add disappears; Replace/Remove originals return to the scenario. Reset all changes clears operations while retaining name, dates and reserves. Neither action changes the ledger or cancels real leave.

The baseline and scenario chart, summary, daily/event tables, lot details, and warnings share one result. A positive final balance does not hide an earlier negative balance or reserve breach. Carryover, pre-cap annual balance, and prospective forfeiture appear only at the actual leave-year end. Hours are not pooled across categories. Purpose-restricted categories stay labeled; projected balances do not grant eligibility.

Working-hour capacity comes from configured workdays, start/end/lunch, cached observed holidays, and existing absences across categories. Capacity conflicts are separate from balance shortfalls. Requested dates and hours are retained, not rescheduled. Missing schedule/holiday context, original lot provenance, and unsupported policies produce warnings and N/A metrics. Irregular rosters and historical knowledge are not reconstructed. Recorded Through Cutoff includes effective past planned/requested rows without asserting attendance; a historical cutoff uses current records, not what was known at that earlier time.

Export scenario JSON saves a versioned definition with assumptions, source identity, and reference fingerprints. Import requires Replace or Merge and checks a fresh read-only snapshot; invalid or stale operations do not partially change the active scenario. Unrelated source edits do not invalidate unchanged references. Refresh rechecks source data; review and explicitly resolve stale references or remove their scenario rows. CSV includes filters, cutoff/horizon, units, reserves, assumptions, provenance, and warnings. Open Chart offers its exact supporting table, CSV, PNG, PDF, and Print.

Scenarios are session-only, with an indicator for changes since import/export. There is no Apply to Ledger. The planner never writes, initializes, migrates, synchronizes, or backs up leave records, including on failed validation, cancellation, or close. Save exports outside the canonical datastore. Calculations run in workers and stale results are discarded.

Leave Budget by deadline

Choose Analysis > Planning > Leave Budget..., or Planning > Leave Budget in Analytics. Set a cutoff/horizon inside the initialized year, explicitly select purpose-eligible categories, and optionally enter reserve hours beside each category. No eligibility is assumed. Suggestions are planning suggestions, not booked leave.

Annual required use is max(0, projected pre-cap balance minus carryover cap), after accruals, scheduled use and known disposals. A 288-hour projection with a 240-hour cap needs 48 hours; another 16 scheduled hours yields 272 pre-cap and 32 required, with no double subtraction. Dated lots report original/local hours, cutoff remaining, eligible scheduled use, other disposals, inclusive deadline and actual warn/expiration/forfeiture outcome. Unproven openings are N/A; later deadlines are Outside current horizon, and past dispositions/warnings are separate. Midyear horizons do not claim completed year-end annual risk.

Even across pay periods (default) assigns equal capped period quotas and redistributes overflow. Earliest available fills early dates; Latest available fills late dates before each deadline; Capacity-weighted apportions by eligible period hours. Equal/weighted quotas use stable largest remainders and earliest dates within periods. Every strategy honors earliest-deadline priority, then category/earned date/lot ID. Only the strategy preference is saved, outside the ledger.

Actual pay periods, current configured workdays/tour/lunch and cached observed holidays determine capacity after existing absence across all categories. Future rosters are not reconstructed. Suggestions are strictly after cutoff, respect earning dates, lot links, reserves, future bookings, deadlines and increments, and never move existing bookings. Partial current periods are marked. The unrounded required/usable-period average is separate from rounded suggestions. Missing context stays N/A. Two 16-hour lots sharing 24 hours leave eight hours unallocated.

Deadline, period/date suggestions, daily capacity, cumulative chart/table, before/after balances, source/allocation audit and warnings share one result. Feasibility distinguishes no additional use, feasible, partially feasible, infeasible and unknown/unsupported. Partial suggestions remain visible; residual risk is recomputed canonically. The cumulative table also exposes a dated joint-capacity upper bound; shared reserves/caps are additionally checked on the actual schedule. A chosen-strategy shortfall does not prove every alternative impossible. Supported credit caps replay once at actual period boundaries; unsupported policies warn without disabling other categories. The opt-in planning assumption is preserved in What-if and does not change default CLI accounting.

Double-click a result row for exact details, including dated funding failures and reserve thresholds. Save any table as CSV with exact values, source/version, strategy, filters, rules and assumptions. Open Chart provides exact data, CSV, PNG, PDF and Print. Send suggestions to What-if checks a fresh read-only snapshot and creates in-memory Add operations. Existing drafts require Replace, Merge or Cancel; merge retains existing operations and adopts budget assumptions/reserves, so its combined result can differ. Changed material source/context rejects stale transfer. Recorded Through Cutoff includes unresolved past planned/requested rows; future source rows are Scheduled; suggestions are Estimated. No opening, calculation, export, transfer, cancellation or close action writes canonical leave records.

Usage Forecast

Choose Analysis > Planning > Usage Forecast..., or Planning > Usage Forecast in Analytics. Select annual, sick, or combined annual/sick; a cutoff/horizon inside the selected year; optional per-category reserves; and historical reference years. The default reference list is the five most recent prior years. Uncheck Reference or mark Exclude unusual to control the inclusion list.

Usage Forecast is a read-only planning and analysis feature. It does not create, modify, or delete leave transactions. Forecast calculations use isolated in-memory data, and historical coverage preferences are stored separately from leave records.

Coverage starts unconfirmed. Select a year and confirm the whole year or selected represented pay periods only when its leave records are complete. Revoke confirmations whenever needed. A valid calendar alone does not establish completeness: confirmed zero-use periods contribute zero, while unconfirmed/stale periods remain missing. Material source changes require renewed confirmation; display-only changes do not.

Scheduled preserves all effective entered leave. Typical Usage uses median historical month/exposure estimates; Higher Usage uses the historical 80th percentile with linear interpolation. At least three eligible seasonal year observations are needed; otherwise an independently eligible whole-year rate is used, with one/two years labeled Limited history. No usable history leaves Scheduled available and estimates N/A. Optional confirmed-status history uses worked, submitted, certified and reconciled rows; past planned/requested rows remain unresolved Recorded Through Cutoff.

Additional estimated use is calculated separately for each category and month segment: max(0, estimated total minus scheduled use). If Typical/Higher estimate 32/40 hours and 24 are scheduled, only 8/16 are added; 48 scheduled hours remain 48 with no additional estimate. Annual and sick balances remain separate. Combined estimates share remaining work hours proportionally, including existing absence in other categories, with deterministic time-increment allocation. Leave-balance shortages do not cap usage; negative balances remain visible.

Current configured workdays, tour/lunch and cached observed holidays determine exposure when historical schedules are unavailable; the retrospective schedule assumption is disclosed. Missing schedule/holiday coverage produces unknown exposure. The same month number at both leave-year edges is combined for historical rates, while target segments remain distinct. Incomplete Allocation shows allocated and unallocated hours. Daily curves/horizon values include only allocated estimates. Hypothetical full-demand balances are separately labeled and show N/A when undated demand has timing-dependent expiration or year-end effects; no fictional dates are assigned.

Monthly explanations include source years, per-year rates, seasonal/fallback eligibility, scheduled use, additional demand and allocated closing balances. Double-click a monthly row for source IDs, rates and coverage reasons. Source transactions, daily balances, synthetic allocations, events, lots and warnings use the same result. Save any table as CSV with method/version/filters/assumptions; Export Results JSON includes the full result. Open Chart offers exact supporting daily data, CSV, PNG, PDF and Print. Historical scenarios are not calibrated probabilities or confidence intervals.

Retrospective usage check evaluates represented pay-period-end cutoffs in a completed historical year, training only on selected earlier years. It reports Typical/Higher errors and MAE, sample counts and a whole-year-rate comparison with training populations disclosed. Present records do not reconstruct which bookings/statuses were known at an earlier cutoff: these checks validate usage estimation, not the operational accuracy of forecasts issued then.

Preferences

Preferences can set a backend executable, optional data directory, first day of week, display toggles, font size, print orientation, and PDF export folder.

Printing and PDF Export

Print preview, printer output, and PDF export use the same landscape month-report graphic layout as fedleaveMonthReportGraphic. Reports do not show zero values.

Troubleshooting

If the backend cannot be found, open Preferences and set the fedleave executable path. In a packaged install, the GUI expects the companion executables and shared runtime to remain together. The GUI does not fabricate data after backend failures. For current installation and support information, visit the official project website above.
